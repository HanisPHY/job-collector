## 3. 给工程师的注意事项

### E1 ⚠️ 最重要：§3.1 说 `REL_INC` 大小写敏感，**按字面实现会把段① 从 28 打到 9**

规格自己的数字（§3 表：8/19 = 13、8/20 = 28）是在**正文大小写不敏感**下测出来的。
但 §3.1 的注释写「`REL_INC` 大小写敏感」，而 `REL_INC` 里全是小写字面量 ——
`Software Engineer, New Grad` 匹配不上 `new\s*grad`。我两种都跑了：

| 实现 | 8/19 段① | 8/20 段① | 8/20 默认可见 | F10 [20,45] | F11 [30,55] |
|---|---|---|---|---|---|
| **按 §3.1 字面（全敏感）** | 2 | **9** | 20 | ❌ | ❌ |
| **正文 `re.I` + 后缀 `\b(?:I\|1)$` 保持敏感** | **13** | **28** | 39 | ✅ | ✅ |

第二种与 §3 表逐格吻合。**正确写法是把大小写敏感的范围限定在后缀标级那一项上**：

```python
REL_BODY = re.compile(r"new\s*grad|new college|entry[ -.]level|university|campus|graduat|"
                      r"intern(?!ational)|202[6-8]|junior|associate|apprentic|"
                      r"early career|rotational", re.I)      # 正文：不敏感
REL_SUF  = re.compile(r"\b(?:I|1)$")                          # 后缀标级：敏感
def is_entry(t):
    t = (t or "").strip()
    return bool(REL_BODY.search(t) or REL_SUF.search(t)) and not REL_EXC.search(t)
```

不改的话工程师会撞上「fixture 红了但代码跟规格一字不差」，会浪费半天。

### E2 F13 与 F10 自相矛盾

F10 断言段① = 28 行，F13 断言「段① **前 30 行** 30/30 是应届岗」—— 28 行里取不出 30 行。
改成「段① 全部 28 行」或「段①+② 的前 30 行」，二选一。

### E3 F11 的区间只在 8/20 成立，ATS 收割日会撑爆默认可见

实测 8/19 默认可见 = **83 行**（段① 13 + B1 **70**）。§3 的脚注承认 8/19 的 70 是
`ats_direct` 首日全量的一次性效应、稳态 10 行 —— 这没错，但**只要以后往
`ats_registry.json` 里加一批新 board，同样的收割日就会重演一次**，
而 B1 是默认展开的。建议给展开的 B1 一个显示上限（超过 N 行后折叠剩余），
否则 F11 会在扩容后无预警变红。

### E4 cutoff 只能在 dashboard **成功写盘之后**推进

这条在 round2 §1-B2 定义过，round3 §1 只写了「接受」没复述。机器关机、
`dashboard.py` 崩了、磁盘满了 —— 任何一次生成失败都不能推进 cutoff，
否则那一段岗位既不在段①也不在段⑦，只能靠日期条捞。写代码时把推进放在文件写完之后。

### E5 日期条依赖归档 HTML 长期存在

已核实 `prune_logs()`（`daily_report.py:586`）只删 `logs/*/*.log`，`logs/daily/*.html` 安全。
**以后不要为省空间把这个 glob 放宽**，否则段⑦之外的历史入口会被静默清掉。

### E6 配色规范排在 P1，但 P0-5 就要渲染

「A0-B2 五级顺序色阶 + C 单独中性/警示色 + 图标 + 文字」写在 P1 第 8 条，
可 `dashboard.py` 是 P0-5。它是 P0-5 的**规范性输入**，不是可以延后的任务，别按 P1 排期。
另外**深色模式对比度三轮都没人交代过** —— 顺序色阶在深色底上前两级极易糊在一起，
实施时至少手动切两种模式各扫一眼。

### E7 fixture 的期望值请用区间，F12 的等式今天就已经不成立

语料是活的。§3 写「当日去重后 931」，我复核时已经是 **996**（采集器一直在跑），
段① 仍然是 28、B1 仍然是 10、raw 合计仍然自洽。
所以 **F12「931 == 931」不能写成常数等式**，要写成「各段 raw 之和 == 当日去重后行数」
这个**恒等式**（我验过它成立）。同理 F10/F11 保留区间、不要写死 28/38。

### E8 相关性正则不看职能

B1 里的 `Technical Recruiter - New Grad`、段① 里的 `Mechanical Engineer Entry Level`、
`ENGINEER PLANNING ANALYST 1` 都会被判为「应届相关」。这是已知的、可接受的
（P1 第 1 条的岗位相关性过滤会收掉一部分），别当 bug 修，也别为它加特例。
