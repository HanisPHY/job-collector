1. Original requirement

Let the user view the past N days (N ∈ {1, 3, 7, 14, 30}) of segmented job postings and pick from them to apply (R2, core); trend chart follows N (R1); clicking the stacked bar jumps to the segment (R3); split the 583-line HTML-string renderer into real .html/.css/.js (R4). Nine judgment-layer invariants I1–I9 and the six segment criteria were settled, not open. Applied/ignored tracking was explicitly excluded by the user on 2026-08-21.

Intake re-measured at 02:10: 2,491 rows (8/19 287 · 8/20 2,072 · 8/21 132), 36 tests = 34 pass + 2 skip. The corpus grew to 2,713 rows by the time the build finished — every number below is tagged with its measurement time in the underlying documents.

3. Approved design

dashboard_loop/v2/design_v3.md (v3.2, 1,002 lines). In one breath:

  • Division of labour. Python decides everything (segment, tier/prom, sort rank, dedup bit, checksum expectations); dashboard.js filters, counts, builds DOM and reconciles. F23 greps the JS for judgment vocabulary and hard-coded segment arrays.
  • Data. data-index.js + one data-<day>.js per calendar day (≈75–98 B/row), rewritten daily under today's resolver; latest.html is the only page; --out DIR produces a frozen self-contained bundle.
  • First screen. open_plan: ①/④ capped at 35/12, ② fills only up to FLOOR 30; contract min(FLOOR, openable) ≤ open ≤ 47 with 47 derived, never typed. Measured at the real 08:00 generation hour — the previous "47-row" figures were all end-of-day.
  • Two sevens. The judgment window is w7, a constant in the payload; the viewing window is N. They never meet.
  • Guards for what left Python. view.py reference impl asserted by fixtures → runtime check[view][N] (Σraw = dedup, per-segment counts, head sequence, chunk row counts, anchors, order checksums) → red banner → F24 drives the real page in headless Chrome → a mandatory break-it-on-purpose drill.

7. Known limitations and follow-ups

  • Edge unverified. file:// behaviour (dynamic script injection, localStorage) is measured in Chrome only. One human double-click in Edge closes DoD #6.
  • Only three days of corpus. N = 3/7/14/30 currently render the same rows; the chunk-injection path for not-yet-loaded days is exercised by F24/unit tests with synthetic days, not by real data yet.
  • Daily rewrite volume. All retained day chunks are rewritten each morning (≈4.5 MB/day at 2,000 rows/day) so historical rows carry today's judgment. A frozen-chunk + patch scheme (rejected as R5) is the first optimization if OneDrive sync becomes noisy.
  • Repetition across days is inherent to a window view and was a known, accepted consequence; the "new" / "unhandled" views mitigate it (first-screen day-to-day repeat 39–42% → 2–3%) without persisting user state. Applied/ignored remains out of scope.
  • Nothing is committed. Working tree: dashboard.py, tests/test_lane.py, SCHEDULING.md modified; view.py, web/, .claude/agents/, dashboard_loop/v2/ new.
